import { fmt, fmtInt, correlation, mean, min, max, transformedRegression } from '@/lib/stats'
import { ledgerSample, manifest, t9LogLogFit, meanDaysResidual, fuelOnDeclaredFit, fuelOnRequiredFit } from '@/instruments/act-2/data'

export const laneX = ledgerSample.map((t) => t.laneLengthAU)
export const t9Y = ledgerSample.map((t) => t.t9)
export const MODELS = ['none', 'logy', 'logx', 'loglog']
export const MODEL_NAMES = ['raw — a straight line in the original variables', 'log y on raw x — an exponential model', 'raw y on log x', 'log y on log x — a power model']
export const fits = MODELS.map((m) => transformedRegression(laneX, t9Y, m, { base: 10 }))
export const bows = fits.map((f) => {
  const xm = mean(f.tx)
  return Math.abs(correlation(f.residuals, f.tx.map((v) => (v - xm) * (v - xm))))
})
export const flattest = bows.indexOf(min(bows))
export const t9Min = min(t9Y)
export const t9Max = max(t9Y)
export const laneMin = min(laneX)
export const laneMax = max(laneX)
export const lostCount = ledgerSample.filter((t) => t.laterLost).length

export const relay = [
  { range: 22, power: 812 },
  { range: 38, power: 284 },
  { range: 61, power: 105 },
  { range: 95, power: 45.8 },
  { range: 140, power: 19.9 },
  { range: 210, power: 9.31 },
  { range: 300, power: 4.38 },
  { range: 390, power: 2.58 },
]
export const relayX = relay.map((r) => r.range)
export const relayY = relay.map((r) => r.power)
export const relayRaw = transformedRegression(relayX, relayY, 'none', { base: 10 })
export const relayLog = transformedRegression(relayX, relayY, 'loglog', { base: 10 })
export const relayBow = correlation(
  relayRaw.residuals,
  relayX.map((v) => (v - mean(relayX)) * (v - mean(relayX))),
)

He stops. It is a real question and he does not have it.

The Bureau does not load fuel per tonne of ship. A hull certified in a close season is being fuelled for a shorter crossing than the identical hull certified three years later at the far end of the cycle. Two hulls with the same declared mass, two different honest fuel loads, and the difference is not error and not fraud. It is orbital mechanics, sitting in the file as scatter.

And the Bureau, being a bureau, has a column for it. *Required fuel*: the Lane-standard load for that mass on that departure's own plotted profile, computed and signed with everything else. It has been in the extract since MET 30, three columns to the right, unexamined, because nobody thought to ask what the Bureau thought it was fuelling.

Plot fuel loaded against required fuel and the smear becomes a line. {fmt(100 * fuelOnRequiredFit.r2, 0)} percent of the variation, a band you could not hide a launch in, and a slope near one — which is what "the Lane loads what the Lane requires" looks like when it is written as a number.

No transformation. The residuals of the raw fit against the right column are flat, and a transform applied to that would have been a cure for a disease the data did not have — and would have cost him the one thing the plot is good for, which is that a slope of one in tonnes per tonne is a sentence anybody can read.

There are points above that line. A small number of them, high, together. He colours by later-lost and they change colour, all of them at once, exactly as they did on the residual plot two days ago, and he says nothing this time because he has learned that much. You have him note the column, the count and the date, and leave it. It is a second finding on a file that already carries one, and a report that arrives with two findings gets half the attention of a report that arrives with one.

Then Sandoval puts the Ledger up, because she has been waiting for him to be finished.

Six years of the Lane Authority's crossings: {fmtInt(ledgerSample.length)} transits, each with the Lane length at its departure and the time it took to reach the Mark 9 region. From {fmt(laneMin, 1)} to {fmt(laneMax, 1)} AU as the geometry opens and closes; from {fmt(t9Min, 0)} days to {fmt(t9Max, 0)} — two months to nearly four.

It is not a line. It is a bow: it climbs fast at the short end, and it keeps climbing, and it flattens, and a straight line laid through it sits above the data at both ends and below them through the middle. Ebele fits the straight line anyway, because he wants to see the residuals, and the residuals are a smile drawn across the plot from one end to the other.

<Briefing title="Departures from linearity" topics={["2.9"]}>
<Briefing.Intuition>
A residual plot that bends has told you the model is the wrong **shape**. There are two honest responses: fit a different shape, or change the variables until a straight line is the right shape for them. The second is usually easier to defend, because everything you already know about slopes, residuals and $s$ carries over to the new variables unchanged.

Logarithms do the work, because they trade multiplication for addition.

- **A power law**, $y = a x^{b}$ — anything where doubling $x$ multiplies $y$ by a fixed factor. Take logs of both sides: $\log y = \log a + b\log x$. Plot $\log y$ against $\log x$ and it is a line, with **slope $b$: the exponent itself**. This is the family physical laws mostly live in, and the fitted slope is a measurement of the law.
- **An exponential law**, $y = a\cdot 10^{\,bx}$ — anything that grows or decays by a fixed factor per unit of $x$. $\log y = \log a + bx$: log the response only, and plot against raw $x$.
- **Log $x$ alone**, $y = a + b\log x$ — a response that rises fast and then flattens without ever bending back.

Which transformation straightens the data tells you which family the law belongs to, and that is information, not bookkeeping.

**Choosing between models.** Fit the candidates, and compare them on their **residual plots** first. r² is a poor referee here: a bowed cloud still rises from left to right, so a wrong-shaped model over a strong relationship posts a large r² without deserving one, and the four candidates will often sit within a hundredth of each other. The residual plot is the diagnostic that can actually fail. The model to keep is the one whose residuals have nothing left to say — a flat band, no bend, no fan.

**Reading and reporting.** Two disciplines, both easy to lose. A slope fitted on a log scale is *not* a rate in the original units: on log–log it is an exponent, and on log-$y$ it is a multiplicative factor of $10^{b}$ per unit of $x$. And a prediction from a log model comes out as a logarithm, so it is **back-transformed** — raised as a power of ten — before it goes anywhere near a report.
</Briefing.Intuition>
<Briefing.Definition>
<Formula tex="y = a x^{b} \;\Longleftrightarrow\; \log y = \log a + b \log x" terms={{ b: 'the exponent — and the slope of the line on log–log axes', a: 'the multiplier; its logarithm is the intercept', y: 'the response, on the original scale' }} label="Power model: straighten with log–log" />

<Formula tex="y = a\cdot 10^{\,bx} \;\Longleftrightarrow\; \log_{10} y = \log_{10} a + b x" terms={{ b: 'the log₁₀ change in the response per unit of x — a factor of 10^b', a: 'the response at x = 0' }} label="Exponential model: straighten with log y" />

<Formula tex="\hat{y} = 10^{\,\hat{a} + \hat{b}\log_{10} x}" terms={{ '\\hat{y}': 'the prediction, back-transformed into the units of the response', '10^{(\\cdot)}': 'undoing the log — without it the prediction is a logarithm, not a quantity' }} label="Back-transforming a prediction" />
</Briefing.Definition>
<Briefing.Worked>
Solberg's link budget, {relay.length} relay passes: the power the receiver saw (nW) against the range to the relay (Mm).

{relay.map((r) => `${fmt(r.range, 0)} Mm / ${fmt(r.power, 2)} nW`).join(' · ')}

A straight line through the raw pairs gets $r^2$ = {fmt(relayRaw.r2, 4)} — high enough that a careless report would stop there. Its residuals do not stop there. Their correlation with $(x-\bar{x})^2$ is {fmt(relayBow, 2)}: they run {relayBow > 0 ? 'positive at both ends of the range and negative through the middle' : 'negative at both ends of the range and positive through the middle'} — the signature of a curve being described by a line.

Log both axes and fit again:

<Formula tex={`\\log_{10}\\hat{y} = ${fmt(relayLog.fit.intercept, 4)} ${relayLog.fit.slope < 0 ? '-' : '+'} ${fmt(Math.abs(relayLog.fit.slope), 4)}\\log_{10}x`} label="The same passes, on log–log axes" />

$r^2$ = {fmt(relayLog.r2, 5)}, and the residuals are flat. The slope is {fmt(relayLog.fit.slope, 3)} — which is not "{fmt(relayLog.fit.slope, 3)} nW per Mm", a sentence with no meaning. It is an **exponent**: received power is proportional to range to the power {fmt(relayLog.fit.slope, 3)}, near enough to −2, and the inverse-square law has fallen out of eight rows of a comms log.

Predict at 250 Mm. The line gives a logarithm first:

<Formula tex={`\\log_{10}\\hat{y} = ${fmt(relayLog.fit.intercept, 4)} ${relayLog.fit.slope < 0 ? '-' : '+'} ${fmt(Math.abs(relayLog.fit.slope), 4)}\\log_{10}(250) = ${fmt(relayLog.fit.intercept + relayLog.fit.slope * Math.log10(250), 4)}`} label="Evaluate on the fitted scale" />

<Formula tex={`\\hat{y} = 10^{${fmt(relayLog.fit.intercept + relayLog.fit.slope * Math.log10(250), 4)}} = ${fmt(relayLog.predict(250), 2)}\\ \\text{nW}`} label="Back-transform before reporting" />

{fmt(relayLog.predict(250), 2)} nW. The number in the middle — {fmt(relayLog.fit.intercept + relayLog.fit.slope * Math.log10(250), 4)} — is a logarithm of nanowatts and belongs in no report ever written.
</Briefing.Worked>
<Briefing.Caution>
*"r² is high, so the model is fine."* r² measures how much of the variation a line accounts for, not whether a line was the right shape. The raw fit above reaches {fmt(relayRaw.r2, 3)} and is wrong. Look at the residual plot; it is the only one of the two that can fail.

*Reading a log-scale slope in raw units.* On log–log the slope is an exponent; on log-$y$ it is a factor of $10^{b}$ per unit of $x$. "Per Mm" and "per tonne" are sentences about a straight line in the original variables, and the original variables are bowed — which is why the transformation was made.

*Reporting the transformed prediction.* A log model predicts a logarithm. Raise it as a power of ten before it goes in the file; a prediction in log-days is not a prediction in days.

*Transforming by reflex.* A transformation is a remedy. If the raw residuals are already a flat band there is no disease, and logging the axes only costs you a slope the reader could have used.
</Briefing.Caution>
</Briefing>
