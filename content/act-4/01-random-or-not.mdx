export const clusterSe = Math.sqrt((P_CLUSTER_SIMULATED * (1 - P_CLUSTER_SIMULATED)) / CLUSTER_RUNS)
/** The tightest window in the Register, located from the loss dates themselves rather than asserted. */
export const dayIndex = (iso) => Math.round((Date.parse(iso + 'T00:00:00Z') - Date.UTC(2178, 0, 1)) / 86400000)
export const clusterWindow = (() => {
  const sorted = [...lossDates].sort()
  let best = []
  for (const start of sorted) {
    const run = sorted.filter((d) => dayIndex(d) >= dayIndex(start) && dayIndex(d) - dayIndex(start) <= CLUSTER_WINDOW_DAYS)
    if (run.length > best.length) best = run
  }
  return best
})()
export const clusterFrom = clusterWindow[0]
export const clusterTo = clusterWindow[clusterWindow.length - 1]
export const clusterSpan = dayIndex(clusterTo) - dayIndex(clusterFrom)
export const asDate = (iso) => new Date(iso + 'T00:00:00Z').toLocaleDateString('en-GB', { day: 'numeric', month: 'long', year: 'numeric', timeZone: 'UTC' })
export const hullList = CLUSTER_HULLS.map((h) => `*${h}*`).join(', ')
/**
 * The Briefing's worked study — a different file, a different question, run twice at two run sizes so
 * the estimate can be watched to wander. Ceres receiving office: 26 reweighs over a 180-day season,
 * six of them inside one ten-day stretch. Every figure is simulated at load by the same engine the
 * instrument uses; nothing here is typed in by hand.
 */
export const CERES = { reweighs: 26, seasonDays: 180, windowDays: 10, observed: 6 }
export const ceresStudy = (runs, key) => {
  const r = rng('act-4-01', 'worked', key)
  const stats = []
  for (let i = 0; i < runs; i++) stats.push(simulateCluster(r, CERES.reweighs, CERES.seasonDays, CERES.windowDays))
  const counts = new Map()
  for (const s of stats) counts.set(s, (counts.get(s) ?? 0) + 1)
  return {
    runs,
    distribution: [...counts.entries()].sort((a, b) => a[0] - b[0]).map(([value, count]) => ({ value, count })),
    atOrAbove: stats.filter((s) => s >= CERES.observed).length,
    mean: stats.reduce((a, b) => a + b, 0) / runs,
  }
}
export const ceresFirst = ceresStudy(200, 'first-pass')
export const ceresFull = ceresStudy(2000, 'full')
export const ceresPFirst = ceresFirst.atOrAbove / ceresFirst.runs
export const ceresP = ceresFull.atOrAbove / ceresFull.runs
export const ceresSeFirst = Math.sqrt((ceresPFirst * (1 - ceresPFirst)) / ceresFirst.runs)
export const ceresSe = Math.sqrt((ceresP * (1 - ceresP)) / ceresFull.runs)

<Briefing title="What random looks like, and how to ask it a question" topics={["4.1", "4.2"]}>
<Briefing.Intuition>
**The long run is the only run that is flat.** A probability is what a relative frequency settles to as the number of trials grows without bound — the law of large numbers — and that is a statement about infinity, not about your afternoon. Over ten thousand sweeps a six per cent detection rate shows up as six per cent. Over twelve sweeps it shows up as nothing at all, or as four in a row, and both of those are ordinary.

So two errors follow from forgetting it, and they point in opposite directions.

- **The gambler's fallacy.** Nine clean sweeps in a row, so the tenth is "due". It is not. Independent trials have no memory and keep no accounts. The long-run rate is reached by *swamping* an early run with thousands of later trials, never by correcting it.
- **"Random means evenly spread."** A uniform scatter of dates is not a regular scatter of dates. It has gaps and it has clumps, and a file with neither would be the strange one. Evenly spaced is the *opposite* of random: it is a pattern, and a model built that way has the answer already inside it.

Which means an eye cannot judge a clump. Only a model can — and that is the second idea.

**A simulation is an argument with three parts, all stated before any code runs.**

1. **The model.** What chance alone is assumed to do, and *nothing else*. This is where simulations are usually lost. If the observation was "five losses in one month", the model must not fix the count at five, must not adopt the rate the data happened to show, and must not space the dates evenly. It carries the assumption being tested, not the result observed.
2. **One trial.** One repetition of the *whole* process that produced the observation. If the statistic is a property of a six-year file, one trial is a whole six-year file — not one loss, not one month.
3. **The statistic.** The single number recorded out of each trial, and it has to be the quantity the question asked about. "The largest cluster anywhere in the period" and "the number of losses inside the window the data pointed at" are different statistics, and only the first is honest, because the second has already looked at the answer.

Then repeat the trial many times, stack the statistic into a distribution, and find where the observed value stands in it. The **simulated probability** is the share of trials at or beyond that value.

**And it is an estimate.** Run the same model twice and you get two different numbers. That is not a defect of the method; it is the most honest property it has, and it is why a simulated probability is reported as a *count out of a run size* and never as a bare percentage. A hundred runs locates a probability to within a couple of percentage points. Ten thousand locates it to within a tenth of one. The model did not change between those two studies — the precision did, and a reader handed only "about two per cent" cannot tell which one they have.

Last, and this is the part a hostile reader attacks: a small simulated probability says the observation is **rare under the model**. It does not say the model is false, and it says nothing whatever about what is true instead. It says *chance alone explains this badly*. What explains it well is a question the simulation has no opinion about.
</Briefing.Intuition>
<Briefing.Definition>

  label="What N buys: quadruple the runs to halve the wobble"
/>
</Briefing.Definition>
<Briefing.Worked>
Not the Register. A file nobody is arguing about, so the method can be watched with nobody's career attached to it.

The Ceres receiving office reweighs arrivals whose manifest looks wrong. Over one {fmtInt(CERES.seasonDays)}-day season it logged {fmtInt(CERES.reweighs)} reweighs, and {fmtInt(CERES.observed)} of them fell inside a single {fmtInt(CERES.windowDays)}-day stretch. A clerk has written *unusual concentration* in the margin.

**The model:** {fmtInt(CERES.reweighs)} reweigh dates scattered uniformly at random across the {fmtInt(CERES.seasonDays)} days. **One trial:** draw all {fmtInt(CERES.reweighs)} dates, walk a {fmtInt(CERES.windowDays)}-day window across them, record the largest number inside it. **The statistic:** that largest cluster. Note what the model does *not* contain: the ten days the clerk noticed, and the six that fell in them.

Ebele's first pass was {fmtInt(ceresFirst.runs)} runs.

<KeyTable

  rows={ceresFirst.distribution.map((d) => [d.value, fmtInt(d.count)])}

  ariaLabel={`Distribution of the largest ${CERES.windowDays}-day cluster across ${ceresFirst.runs} simulated seasons`}
/>

{fmtInt(ceresFirst.atOrAbove)} of those {fmtInt(ceresFirst.runs)} seasons produced a cluster of {fmtInt(CERES.observed)} or more. The estimate is {fmtInt(ceresFirst.atOrAbove)} ÷ {fmtInt(ceresFirst.runs)} = **{fmt(ceresPFirst, 4)}**, and its standard error on {fmtInt(ceresFirst.runs)} runs is about {fmt(ceresSeFirst, 4)} — which is to say the third decimal place of that number is decoration.

Re-run the *same model* with {fmtInt(ceresFull.runs)} trials and the estimate moves.

<Formula
  tex={`\\hat{P}(\\text{largest ${CERES.windowDays}-day cluster} \\ge ${CERES.observed}) = \\frac{${ceresFull.atOrAbove}}{${ceresFull.runs}} = ${fmt(ceresP, 4)}`}
  label={`The Ceres study, ${fmtInt(ceresFull.runs)} runs — standard error about ${fmt(ceresSe, 4)}`}
/>

Neither run is wrong. But **{fmt(ceresPFirst, 3)} off {fmtInt(ceresFirst.runs)} runs and {fmt(ceresP, 3)} off {fmtInt(ceresFull.runs)} runs are two different claims**, and a reader handed only "about twenty per cent" cannot tell them apart.

Now the finding, which is why anyone ran it. Chance alone scatters {fmtInt(CERES.reweighs)} reweighs into a {fmtInt(CERES.windowDays)}-day clump of {fmtInt(CERES.observed)} or more {inAHundred(ceresP)} seasons. The mean largest cluster under pure chance is {fmt(ceresFull.mean, 2)} — the clerk's *unusual concentration* is barely above what an ordinary season produces, and chance makes one at least that tight about one season in five. **There is nothing to investigate at Ceres.** That is a real result, it cost {fmtInt(ceresFull.runs)} imaginary seasons, and it is the same machine you are about to point at the Register.
</Briefing.Worked>
<Briefing.Caution>
*The gambler's fallacy.* "Nine quiet transits, so one is owed." Nothing is owed. Every trial carries the probability it always carried, and "the run has to break sooner or later" is a true statement about the long run being traded for a false one about the next trial.

*"Random means evenly spread."* Clumping is not evidence against randomness; clumping is what randomness produces at short range. When you eyeball a file and a stretch looks crowded you have learned nothing yet. A cluster becomes information only after a model has said how often chance makes one that size — and the model is allowed to surprise you in the other direction, which is exactly what Ceres just did.

*A simulated estimate reported as exact.* {fmt(ceresP, 4)} has the shape of a computed probability. It is a count of {fmtInt(ceresFull.atOrAbove)} out of {fmtInt(ceresFull.runs)} imaginary seasons, and it would come out differently tomorrow. Give the count and the run size every time: a simulated probability carries its run size the way a measurement carries its instrument.

*Rare under the model, read as "the model is false" — or worse, as "my explanation is true".* A simulation prices an observation under chance alone. It nominates no replacement, and it cannot distinguish between the four explanations you have not thought of yet.
</Briefing.Caution>
</Briefing>
