export const heat = heatFor('act-4-01')
export const clusterSe = Math.sqrt((P_CLUSTER_SIMULATED * (1 - P_CLUSTER_SIMULATED)) / CLUSTER_RUNS)
/** The tightest window in the Register, located from the loss dates themselves rather than asserted. */
export const dayIndex = (iso) => Math.round((Date.parse(iso + 'T00:00:00Z') - Date.UTC(2178, 0, 1)) / 86400000)
export const clusterWindow = (() => {
  const sorted = [...lossDates].sort()
  let best = []
  for (const start of sorted) {
    const run = sorted.filter((d) => dayIndex(d) >= dayIndex(start) && dayIndex(d) - dayIndex(start) <= CLUSTER_WINDOW_DAYS)
    if (run.length > best.length) best = run
  }
  return best
})()
export const clusterFrom = clusterWindow[0]
export const clusterTo = clusterWindow[clusterWindow.length - 1]
export const clusterSpan = dayIndex(clusterTo) - dayIndex(clusterFrom)
export const asDate = (iso) => new Date(iso + 'T00:00:00Z').toLocaleDateString('en-GB', { day: 'numeric', month: 'long', year: 'numeric', timeZone: 'UTC' })
export const hullList = CLUSTER_HULLS.map((h) => `*${h}*`).join(', ')
/**
 * The Briefing's worked study: a different file, a different question, run twice at two run sizes so
 * the estimate can be watched to wander. Ceres receiving office, 26 reweighs over a 180-day season,
 * six of them inside one ten-day stretch. Every figure is simulated at load by the same engine the
 * instrument uses; nothing here is typed in by hand.
 */
export const CERES = { reweighs: 26, seasonDays: 180, windowDays: 10, observed: 6 }
export const ceresStudy = (runs, key) => {
  const r = rng('act-4-01', 'worked', key)
  const stats = []
  for (let i = 0; i < runs; i++) stats.push(simulateCluster(r, CERES.reweighs, CERES.seasonDays, CERES.windowDays))
  const counts = new Map()
  for (const s of stats) counts.set(s, (counts.get(s) ?? 0) + 1)
  return {
    runs,
    distribution: [...counts.entries()].sort((a, b) => a[0] - b[0]).map(([value, count]) => ({ value, count })),
    atOrAbove: stats.filter((s) => s >= CERES.observed).length,
    mean: stats.reduce((a, b) => a + b, 0) / runs,
  }
}
export const ceresFirst = ceresStudy(200, 'first-pass')
export const ceresFull = ceresStudy(2000, 'full')
export const ceresPFirst = ceresFirst.atOrAbove / ceresFirst.runs
export const ceresP = ceresFull.atOrAbove / ceresFull.runs
export const ceresSeFirst = Math.sqrt((ceresPFirst * (1 - ceresPFirst)) / ceresFirst.runs)
export const ceresSe = Math.sqrt((ceresP * (1 - ceresP)) / ceresFull.runs)

<Briefing title="What random looks like, and how to ask it a question" topics={["4.1", "4.2"]}>
<Briefing.Intuition>
**The long run is the only run that is flat.** A probability is the value a relative frequency settles to as the number of trials grows without bound. That is the law of large numbers, and it is a statement about infinity rather than about your afternoon. Over ten thousand sweeps a six per cent detection rate shows up as six per cent. Over twelve sweeps it shows up as nothing at all, or as four in a row. Both of those are ordinary.

Forgetting that produces two errors, and they point in opposite directions.

- **The gambler's fallacy.** Nine clean sweeps in a row, so the tenth is "due". Independent trials have no memory. The long-run rate is reached by *swamping* an early run with thousands of later trials, never by correcting it.
- **"Random means evenly spread."** Random scatter produces gaps and clumps, and a file with neither would be the strange one. Evenly spaced is a pattern, and a model built that way has the answer inside it already.

An eye cannot judge a clump. A model can, and that is the second idea.

**A simulation is an argument with three parts, all stated before any code runs.**

1. **The model.** What chance alone is assumed to do, and *nothing else*. This is where simulations are usually lost. A model built to reproduce the observation can no longer price it: if the observation was a tight clump of losses, the model must not fix the size of the clump, and must not borrow the spacing the data happened to show. It carries the assumption being tested.
2. **One trial.** One repetition of the *whole* process that produced the observation. If the statistic is a property of a six-year file, then one trial is a whole six-year file.
3. **The statistic.** The single number recorded out of each trial. It has to be the quantity the question asked about. *The largest cluster anywhere in the period* and *the number of losses inside the window the data pointed at* are different statistics. The second has already looked at the answer, so only the first can price it.

Then repeat the trial many times, stack the statistic into a distribution, and find where the observed value stands in it. The **simulated probability** is the share of trials at or beyond that value.

**The result is an estimate.** Run the same model twice and you get two different numbers. Report a simulated probability as a *count out of a run size*, never as a bare percentage. A hundred runs locates a probability to within a couple of percentage points; ten thousand locates it to within a tenth of one. The model is identical across those two studies. The precision is not, and a reader handed a bare percentage cannot tell which one they have.

A small simulated probability says the observation is **rare under the model**. It does not say the model is false, and it says nothing about what is true instead. Chance alone explains the observation badly. What explains it well is a question the simulation has no opinion about.
</Briefing.Intuition>
<Briefing.Definition>
<Formula

  terms={{ '\\hat{p}_n': 'the relative frequency after n trials: the thing you can see', 'P(A)': 'the probability: the value the relative frequency settles to', n: 'number of trials' }}
  label="Probability as a long-run relative frequency (the law of large numbers)"
/>

<Formula

  terms={{ t: 'the observed value of the statistic', N: 'how many trials were run; always reported with the estimate' }}
  label="A simulated probability is a count over a run size"
/>

<Formula

  terms={{ '\\mathrm{SE}(\\hat{p})': 'how far the estimate typically moves when the study is re-run', '\\hat{p}': 'the simulated estimate' }}
  label="What N buys: quadruple the runs to halve the wobble"
/>
</Briefing.Definition>
<Briefing.Worked>
A different file, and one nobody is arguing about.

The Ceres receiving office reweighs arrivals whose manifest looks wrong. Over one {fmtInt(CERES.seasonDays)}-day season it logged {fmtInt(CERES.reweighs)} reweighs, and {fmtInt(CERES.observed)} of them fell inside a single {fmtInt(CERES.windowDays)}-day stretch. A clerk has written *unusual concentration* in the margin.

**The model:** {fmtInt(CERES.reweighs)} reweigh dates scattered uniformly at random across the {fmtInt(CERES.seasonDays)} days. **One trial:** draw all {fmtInt(CERES.reweighs)} dates, walk a {fmtInt(CERES.windowDays)}-day window across them, record the largest number inside it. **The statistic:** that largest cluster. Note what the model does *not* contain: the {fmtInt(CERES.windowDays)} days the clerk noticed, and the {fmtInt(CERES.observed)} that fell in them.

Ebele's first pass was {fmtInt(ceresFirst.runs)} runs.

/>

{fmtInt(ceresFirst.atOrAbove)} of those {fmtInt(ceresFirst.runs)} seasons produced a cluster of {fmtInt(CERES.observed)} or more. The estimate is {fmtInt(ceresFirst.atOrAbove)} ÷ {fmtInt(ceresFirst.runs)} = **{fmt(ceresPFirst, 4)}**, and its standard error on {fmtInt(ceresFirst.runs)} runs is about {fmt(ceresSeFirst, 4)}. The third decimal place of that estimate is decoration.

Re-run the *same model* with {fmtInt(ceresFull.runs)} trials and the estimate moves.

<Formula
  tex={`\\hat{P}(\\text{largest ${CERES.windowDays}-day cluster} \\ge ${CERES.observed}) = \\frac{${ceresFull.atOrAbove}}{${ceresFull.runs}} = ${fmt(ceresP, 4)}`}
  label={`The Ceres study at ${fmtInt(ceresFull.runs)} runs, standard error about ${fmt(ceresSe, 4)}`}
/>

Neither run is wrong. But **{fmt(ceresPFirst, 3)} off {fmtInt(ceresFirst.runs)} runs and {fmt(ceresP, 3)} off {fmtInt(ceresFull.runs)} runs are two different claims**, and a reader handed only a rounded percentage cannot tell them apart.

Now the finding. Chance alone scatters {fmtInt(CERES.reweighs)} reweighs into a {fmtInt(CERES.windowDays)}-day clump of {fmtInt(CERES.observed)} or more in {inAHundred(ceresP)} seasons. The mean largest cluster under chance alone is {fmt(ceresFull.mean, 2)}, so the clerk's *unusual concentration* sits barely above an ordinary season. **There is nothing to investigate at Ceres.** That is a real result, and it cost {fmtInt(ceresFull.runs)} imaginary seasons.
</Briefing.Worked>
<Briefing.Caution>
*The gambler's fallacy.* "Nine quiet transits, so one is owed." Nothing is owed. Every trial carries the probability it always carried, and "the run has to break sooner or later" is a true statement about the long run traded for a false one about the next trial.

*"Random means evenly spread."* Clumping is not evidence against randomness; clumping is what randomness produces at short range. When you eyeball a file and a stretch looks crowded you have learned nothing yet. A cluster becomes information only after a model has said how often chance makes one that size, and the model is allowed to answer in the other direction, as Ceres did.

*A simulated estimate reported as exact.* {fmt(ceresP, 4)} has the shape of a computed probability. It is a count of {fmtInt(ceresFull.atOrAbove)} out of {fmtInt(ceresFull.runs)} imaginary seasons, and it would come out differently tomorrow. Give the count and the run size every time.

*Rare under the model, read as "the model is false", or as "my explanation is true".* A simulation prices an observation under chance alone. It nominates no replacement, and it cannot distinguish among the explanations you have not thought of yet.
</Briefing.Caution>
</Briefing>
