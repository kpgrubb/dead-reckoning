<Briefing title="Individuals and variables" topics={["1.2"]}>
<Briefing.Intuition>
Before a data table can say anything, you have to be able to say what one row is.

The **individuals** are the things being described, one per row. The **variables** are what is recorded about each individual, one per column. Change what a row is and every variable in the table changes meaning with it.

Variables come in two kinds.

A **categorical** variable places each individual in a group: *Quiet / Watch / Standby*, *detected: yes / no*, hull number *CX-1*. You tally categorical data and report counts or proportions. You never average it, and digits do not change that. A hull number and a cause code are labels that happen to be written with numerals.

A **quantitative** variable measures or counts, and arithmetic on it is meaningful. Quantitative variables split again:

- **Discrete:** a count. Purges in a run, people aboard, fixes logged. It moves in whole steps and there is nothing between 2 and 3.
- **Continuous:** a measurement that can take any value in an interval. Hours, kilowatts, percent of capacity, temperature. The instrument rounds it; the quantity itself does not.

Every quantitative variable carries **units**. A quantitative value reported without its units is not yet data.
</Briefing.Intuition>
<Briefing.Definition>
<Formula tex="E = \frac{C}{L}" terms={{ 'E': 'endurance — hours until the sink is full (quantitative, continuous)', 'C': 'sink capacity, joules (a constant of the ship)', 'L': 'load, watts (quantitative, continuous; varies run to run)' }} label="Endurance of the cellar at a steady load" />

Individuals = the rows. Variables = the columns: **categorical** (groups; tally) or **quantitative** (numbers with units; average), and quantitative variables are **discrete** (counts) or **continuous** (any value in an interval).

Note what $E = C/L$ implies. $C$ is fixed by the hardware. $L$ varies from run to run, so $E$ varies from run to run: endurance is a variable, not a constant of the ship, and a single value of it is one observation rather than a specification.
</Briefing.Definition>

*Individuals:* the three runs, one row each. *Variables:* the six columns after the run label.

*Classification.* **Profile** and **Detected** are categorical: they sort each run into a group. **Hours cold**, **Mean load** and **Sink at end** are quantitative and continuous, in hours, kilowatts and percent. **Purges** is quantitative and discrete: a count, in purges.

*Arithmetic on a quantitative column.* The design endurance on Quiet is capacity over load: {SINK_CAPACITY_GJ} GJ at {PROFILES.Quiet.loadKw} kW gives {fmt(PROFILES.Quiet.designMeanH, 1)} h. Run {a1.run} ran the same profile at {a1.loadKw} kW, which projects {fmt(a1Endurance, 1)} h. The shortfall against the design figure is ({fmt(PROFILES.Quiet.designMeanH, 1)} − {fmt(a1Endurance, 1)}) ÷ {fmt(PROFILES.Quiet.designMeanH, 1)} × 100 = **{fmt(a1Shortfall, 1)} %**.

Same profile, different load, different endurance. The load is the variable; the hours follow it.
</Briefing.Worked>
<Briefing.Caution>
**"The cause code is 3, so it is quantitative."** It is a name written with a numeral. The mean of a set of cause codes names nothing. Test any column by asking whether its mean would mean anything.

**"Continuous means it can be any number."** Continuous means any value in an interval is possible. A sink can read 41.7 percent; a ship cannot make 2.4 purges. A count stays discrete however large it gets.

**Percentage of what.** A shortfall is a fraction of the figure you are measuring against: here, the design endurance. Dividing by the measured endurance instead answers a different question and gives a different number.
</Briefing.Caution>
</Briefing>
